# The Saturday runner image

Two supported variants of one image, built from the same Containerfile with the same entrypoint,
viewer and checks:

| Variant | For | Base |
|---|---|---|
| `debian` (default) | Everyday use, CI, the factory | `node:24.19.0-bookworm-slim`, every package pinned |
| `ubi9` | Teams whose policy requires a Red Hat base, FIPS, or Red Hat's security errata | UBI9 9.x with CentOS Stream 9 and EPEL 9, every package pinned |

Choose with `scripts/ui-suite-in-chrome.sh --ubi9`, or `RUNNER_VARIANT=ubi9`. Both must pass the
same `runner-check` before either ships a change.

An image for running browser suites in real Chrome and Edge under a virtual display, with an
optional VNC viewer. It is built from the best of two existing images, and replaces Saturday's
`containers/ubi-vnc` for the factory and CI. Order `ui-suite-real-chrome` builds it from this page.

## The two images compared

| | Saturday `containers/ubi-vnc` | testing-with-certs `testing/container/Runner*.Containerfile` |
|---|---|---|
| Base | `ubi9/ubi`, unpinned | Debian `node:24.19.0-bookworm-slim` **pinned by digest**; UBI9 9.6 variant, also pinned |
| System packages | Floating; CentOS Stream and EPEL with `gpgcheck=0`, RPM Fusion `--nogpgcheck` | Debian: **all 310 packages pinned** in `apt.lock`; UBI9: Stream and EPEL **signature-checked** |
| Browser signing keys | Fetched at build time | **Vendored, checked against recorded SHA-256** |
| OpenSSL/FIPS | `rpm -e --nodeps openssl-fips-provider-so`, then `--allowerasing` | Stream repos `excludepkgs=openssl*`; UBI's own FIPS packages kept |
| Browsers | Chrome, Edge, plus distro Chromium (unused by Playwright) | Chrome, Edge |
| Node / package manager | Node 22 via `curl \| bash` from NodeSource; `npm install` (this repo uses pnpm) | Node binary copied from the pinned image; **pnpm pinned, `--frozen-lockfile`** |
| Build shape | One stage; `COPY . .` bakes the whole repo into the image | **Multi-stage**: dependencies in a builder, runtime copies only `node_modules` |
| User | root | **uid 1000**, `HOME=/home/runner` |
| Display | supervisord runs Xvfb 1920×1080, openbox, x11vnc | Script runs Xvfb 1366×768 `-nolisten tcp`, waits for it with an **`xdpyinfo` probe**, then the window manager |
| Viewer | x11vnc **with no password, on all interfaces** (`-nopw -listen 0.0.0.0`) | x11vnc with a **random password**, `-localhost`; **noVNC** on 6080, published on 127.0.0.1 only |
| Exit code | supervisord is PID 1, so a test command's exit code is lost | Script `exec "$@"`, so **the command's exit code is the container's** |
| ffmpeg | RPM Fusion, symlinked into `ms-playwright/ffmpeg-1011` (breaks when Playwright moves) | **`playwright install ffmpeg`**, the version Playwright expects |
| Evidence | Prints versions at build | Writes **`installed-packages.txt` and `browser-versions.txt`** into the image |
| Extra toolchains | Java 25 (Oracle "latest"), Python 3.12 built from source, Gradle 9.2 | None |
| Project-specific | Nothing | Certificate trust (`trust.sh`, NSS), managed browser policies, the shop's packages |
| Proven | No recorded runs | Native Linux CI, full browser matrix, Apple Silicon under amd64 emulation |
| WebGL | Not checked | Not checked; automated suites run `headless: true` |

testing-with-certs' image is better on every axis that matters for unattended runs: reproducible,
verified, non-root, a secure viewer, and an honest exit code. Saturday's adds the polyglot
toolchains and a larger screen. Neither has ever shown that WebGL works, which Cesium needs.

## The combined design

**Layered, so both repos share one base.**

```
saturday-runner:debian     Debian bookworm, Chrome, Edge, Xvfb, openbox, VNC/noVNC, Mesa, ffmpeg, Node, pnpm
saturday-runner:ubi9       the same set on UBI9, from UBI, Stream and EPEL
  ├── :debian-polyglot, :ubi9-polyglot   + JDK, Python, Gradle, Go   (optional targets)
  └── testing-with-certs runner          + trust.sh, NSS tools, browser policies   (FROM either, in that repo)
```

**Kept from testing-with-certs**

- `node:24.19.0-bookworm-slim` pinned by digest; every Debian package pinned in `apt.lock`,
  regenerated by a script that resolves and records the closure, never edited by hand.
- Google and Microsoft keys vendored in `containers/saturday-runner/keys/`, checked against
  `SHA256SUMS` before use. The keys are copied from testing-with-certs.
- pnpm pinned; dependencies installed with `--frozen-lockfile`, in a builder stage.
- Non-root uid 1000, `HOME=/home/runner`.
- `playwright install ffmpeg`.
- Evidence files: installed packages, browser versions, and a new one: the WebGL renderer.
- The viewer: random password, `-localhost`, noVNC on 6080, published on 127.0.0.1 only.
- An entrypoint script that starts the display, waits for `xdpyinfo`, starts openbox, and ends in
  `exec "$@"`, so the test command's exit code is the container's. No supervisord.

**Kept from Saturday**

- 1920×1080×24 screen: the reagent map is a desktop view.
- The polyglot toolchains, in an optional `polyglot` target, pinned by version and checksum
  instead of "latest", and installed from release archives rather than built from source.

**New**

- **Mesa GL** (`libgl1-mesa-dri`, `libegl1`, `libgles2`) and **headed** Chrome under Xvfb, so WebGL
  runs on llvmpipe. New-headless Chrome no longer falls back to software WebGL without
  `--enable-unsafe-swiftshader`; headed under Xvfb avoids depending on that flag.
- **`runner-check`**: a command baked into the image that launches Chrome and Edge headed, creates
  a `webgl2` context, and records its renderer to the evidence directory. It fails the build's
  smoke step if either browser gets no context.
- **The repo is mounted, not copied.** The image holds the toolchain; the suite runs against the
  checkout or the factory's worktree mounted at `/work`, with a pnpm store volume. One image serves
  every order without a rebuild, and nothing from the repo ends up in a layer.
- **`RUNNER_VIEWER=1`** starts VNC and noVNC; off by default, so CI and the factory run with no
  listening ports.

**Dropped**

`gpgcheck=0`, `--nogpgcheck`, the `rpm -e --nodeps` FIPS workaround, root, the open VNC server,
distro Chromium, `curl | bash` installers, `COPY . .`, `npm install`, and the ffmpeg symlink.

## Known costs

- **amd64 only.** Google ships no Linux arm64 Chrome. On Apple Silicon the image runs under
  emulation, which testing-with-certs has shown works, slowly. Software WebGL under emulation will
  be slower still, so map tests need generous timeouts there; native Linux CI is the reference.
- **Exact pins fail closed.** Google and Microsoft drop old browser versions from their indexes.
  testing-with-certs hit this on 2026-10-09. When a pinned browser disappears, the build fails and
  the lock is regenerated: deliberately, never silently.
- **Two variants to keep current.** A browser bump lands in both locks, and both run
  `runner-check`. The `ubi9` variant is order `runner-image-ubi9`, designed below.

## The UBI9 variant

**What it does and does not give a team.** It gives a Red Hat lineage, Red Hat's FIPS OpenSSL, and
UBI packages covered by Red Hat's errata. It does not make the image more locked down than the
Debian variant: the display, viewer and software-GL packages come from CentOS Stream and EPEL,
which Red Hat does not support, and the Debian variant pins its packages at least as tightly. Say
which of these a team needs before choosing it for them.


What the repositories hold (checked 2026-10-29):

| Package | UBI9 | CentOS Stream 9 | EPEL 9 |
|---|---|---|---|
| `mesa-libGL`, `mesa-libEGL`, `mesa-libgbm`, `gtk3`, `nss` | yes | yes | |
| `mesa-dri-drivers` (llvmpipe: software WebGL) | **no** | yes, several builds kept | |
| `xorg-x11-server-Xvfb` | **no** | yes, several builds kept | |
| `x11vnc`, `openbox`, `novnc`, `python3-websockify` | **no** | | yes, **latest build only** |

So:

- **A UBI-only image cannot run a virtual display.** Xvfb, the window manager and the viewer come
  from Stream and EPEL, as testing-with-certs already does. If a team's policy is "UBI packages
  only", this image does not meet it, and that is a question for that team before building.
- **WebGL needs `mesa-dri-drivers` from Stream**, which testing-with-certs' UBI9 image does not
  install. Its headed browsers most likely have no software WebGL today; `runner-check` will show it.
- **Mesa comes from one place.** UBI's `mesa-libGL` and Stream's `mesa-dri-drivers` are different
  builds of the same release, and Mesa's subpackages must match. Take every `mesa-*` package from
  Stream (`excludepkgs=mesa*` on the UBI repos), and keep `excludepkgs=openssl*` on Stream as
  testing-with-certs does, for FIPS.
- **Pins:** an `rpm.lock` of exact versions, generated by script like `apt.lock`. Stream keeps
  several builds, so its pins last. EPEL keeps only the latest build, so an EPEL pin breaks at the
  next update. The four EPEL packages are therefore copied into the build context as signed RPMs,
  checked against recorded SHA-256s, and installed from there.
