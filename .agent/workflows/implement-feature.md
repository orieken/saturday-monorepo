# Workflow: Implement & Verify Feature

This workflow guides the agent through an autonomous loop to implement a feature from a UI screenshot, generate tests, and self-heal any failures.

## Prerequisites
- A UI Mockup or Screenshot of the feature to build.
- A clear requirement description (e.g., "Implement Login Page").

## Step 1: Visualization & Modeling
**Goal**: Create the Page Object Model from visual context.

1.  Ask the user to attach the screenshot if they haven't.
2.  Use the `visual_page_object` prompt (via MCP).
    - Arguments: `componentName` (e.g. LoginPage), `path` (e.g. /login).
3.  **Action**: Create the file `lib/pages/<PageName>.ts` with the code generated by the prompt.

## Step 2: Test Generation
**Goal**: Create a verification test for the new page.

1.  Use the `generate_gherkin` prompt/tool or write a Playwright spec directly.
2.  **Action**: Create `tests/<feature>.spec.ts` that imports the new Page Object and asserts basic functionality.

## Step 3: Verification Loop (The "Self-Healing" Core)
**Goal**: Ensure the code works.

1.  **Action**: Run the test using `run_tests`.
    - Arguments: `filter` = "<feature name>"
2.  **Check**: Did it pass?
    - **YES**: Go to Step 4.
    - **NO**: 
        a. Use `parse_test_failure` on the output.
        b. Analyze the error (Missing selector? Wrong text?).
        c. **Heal**: Edit the Page Object or Test file using `replace_file_content`.
        d. **Loop**: Go back to Step 3.1 (Max 3 retries).

## Step 4: Impact Safety Check
**Goal**: Ensure no regressions.

1.  **Action**: Use `analyze_impact`.
    - Arguments: `targetFile` = `lib/pages/<PageName>.ts`
2.  **Output**: Review the list of impacted files.
3.  **Optional**: Suggest running related tests if key dependencies were changed.

## Step 5: Final Handover
1.  Report success to the user.
2.  List created files.
3.  Provide the final test status.
